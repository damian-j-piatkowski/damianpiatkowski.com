# Product Requirement Document: v1.4.0 Dictionary & Admin Panel

## 1. Executive Summary & Core Objective

Milestone 1.4.0 establishes the foundational high-performance lookup system and the comprehensive administrative configuration workspace for the Vietnamese-English language engine. The primary objective is to transition from raw database migrations to an interactive schema mutation engine guarded by structural data safety mechanisms.

> **Note on System Continuity:** The manual configuration architectures built in this release are explicitly engineered to integrate with the upcoming Milestone 1.5.0 Reader. When reading an article in 1.5.0, clicking an unknown word will launch and automatically pre-populate this exact same entry form, allowing manual and automated curation paths to coexist seamlessly.

---

## 2. Admin Authentication & Session Management

Because this platform is engineered for a single administrator, the authentication layer avoids multi-tenant overhead in favor of a secure, lightweight session architecture.

* **User Storage Schema:** Access is authenticated against a single-row `users` table containing an `id`, unique `username`, and a cryptographically hashed password (using `bcrypt` or `scrypt`). No public registration endpoints exist.
* **The Login Workflow:** The admin navigates to a hidden route (e.g., `/admin/login`) to input credentials. Upon confirmation, the Flask backend injects a cryptographically signed cookie session flag: `session["is_admin"] = True`.
* **Route Protection Strategy:** A custom Python decorator, `@admin_required`, intercepts all backend admin API routes (`POST`, `PUT`, `DELETE`). If the signed session flag is missing or invalid, the server immediately aborts the request and returns a `403 Forbidden` status code.

## 4. Detailed User Stories & Functional Workflows

### US1.4.1: Public/Guest Endpoint Search Matrix
* **As a:** Guest (and Admin)
* **I want to:** type alphanumeric characters into the main dictionary input field
* **So that:** I am immediately shown an automated typeahead suggestion matrix.

#### Functional Requirements:
* **Debounced Intercept:** Frontend holds execution until typing pauses for 200ms to stabilize CPU consumption on the server.
* **Admin Extension Layer:** If the backend recognizes that `session["is_admin"]` is `True`, the template engine injects an active "Edit" control anchor directly onto each rendered word block inside the search results view. Clicking this anchor intercepts the page flow, executes an immediate AJAX call to pull the complete relational data payload, and instantly launches the Modification Modal over the current view.

---

### US1.4.2: Dynamic "New Word Creation" Workspace
* **As an:** Authenticated Admin
* **I want to:** trigger a multi-relational input form workspace
* **So that:** I can write a new word, map its structural types, track translations, append citation examples, create sources, and assign Hán Việt root combinations from a single screen.

#### Functional Requirements:
1. **Asynchronous Duplicate Guard:** Once text is added into the main word input, the system runs an automated background query.
   * **Bounce-off Strategy:** Triggers exactly 400ms after typing pauses (giving you space to finish compound terms like *"chính trị"* without flashing alerts prematurely). If an existing record hits, a card pops up: *"Word already exists. Modify entry instead?"* with a link routing directly to the target modification modal.
2. **Dynamic Categories:** The word type attribute is managed as a collection using a separate bridge relationship. Clicking a plus icon appends a secondary type dropdown block, allowing a single word to store multiple grammatical profiles (e.g., Noun and Verb simultaneously) inside `word_type_association`.
3. **Context Sources Pipe:** The source section consists of a source type dropdown (validated string up to 32 characters) paired with a source selection dropdown displaying the 5 most recently used choices for that type. If the target choice is not present, an interactive search/typeahead box handles the lookup. If completely absent, an **"Add New Source"** button reveals two fields: Title and Optional URL. Upon saving the entry, this source record is created in `dictionary_sources` and linked directly to the newly supplied context example sentence.
4. **Hán Việt Prediction Interceptor:** Pressing a **"Check for Existing Roots"** button splits the compound string into component syllables and fires them at the backend database. The UI maps results out into distinct rows:
   * If a component root exists in the DB, show the existing record and provide an explicit **"Associate"** button.
   * If a component root is missing, provide a **"[+] Add New Hán Việt Root"** button that expands the fields necessary to register the new logogram map natively into `han_viet_roots`.
   * If the item is not a Sino-Vietnamese derivative, it can be saved with zero root associations.

---

### US1.4.3: Granular Entry Modification Panels
* **As an:** Authenticated Admin
* **I want to:** launch a focused modification form window for a single word
* **So that:** I can alter individual properties, manage citations, or completely delete records.

#### Functional Requirements:
* **Field Inline Editing:** Base configurations (`english_translation`) display current database records alongside clear edit controls.
* **Citation Multi-Management:** Displays all linked examples from `dictionary_examples` along with their context sources. Admins can drop specific obsolete citations entirely using a trash icon, or append a fresh one using a single-entry submission layout (`sentence`, `english_translation`, and the Dynamic Source Selector).
* **Root Connection Lifecycles:**
  * Clicking **"Unlink"** purges only the cross-reference row in the `word_han_viet_association` bridge schema, keeping the target Hán Việt root entry alive for other words.
  * Clicking **"Delete Root"** executes an application check. Because the database enforces relational safety, the admin interface will reject a hard delete and force an "Unlink" if the root remains attached to any other vocabulary words. A hard destructive wipe of the root from `han_viet_roots` is permitted only when its global association count inside `word_han_viet_association` reaches zero.
* **Destructive Removal Trigger:** A red execution button labeled **"Remove word instead"** sits at the bottom boundary. Activating it displays a clear backdrop-blur overlay window requiring explicit secondary confirmation before running a full row wipe.

## 5. Operational Validation Grid

| Trigger Event / State | Validation & Business Logic Rule | System Behavior / UI Response |
| :--- | :--- | :--- |
| **Word Input Blur** | Value cannot be blank or contain illegal symbol sets. | Halts form progression and highlights the input border in crimson text. |
| **Form Pre-Submission** | Schema constraint verification checks pass across all input fields. | Disables primary save button and outputs a scannable structural alert block on failure. |
| **Root Destruction Action** | Verifies association dependency count is exactly 0 before allowing a hard delete from `han_viet_roots`. | Rejects database delete call if the root is linked elsewhere, switching UI to offer an explicit unlink alternative to safeguard relational integrity. |
| **New Source Appending** | Title cannot be blank when adding custom sources. | Highlights custom title field and prevents final processing payload generation on failure. |

## 6. Core Data & Relationship Requirements

### User Accounts (`users`)
* **Data Collected:** Unique `username` and securely hashed `password` credentials.
* **Rules:** Usernames must be strictly unique across the system.

### Dictionary Vocabulary (`dictionary_words`)
* **Data Collected:** The core Vietnamese word (`viet_word`) and its corresponding `english_translation`.
* **Performance Rule:** The system must optimize lookups for the Vietnamese word to ensure instant search performance via the `idx_viet_word_prefix` index.
* **Relationships:**
  * Can be classified under multiple grammar/word types via `word_type_association`.
  * Can be linked to multiple historical or linguistic roots via `word_han_viet_association`.

### Word Type Classifications (`word_type_association`)
* **Relationships:** A flexible labeling system where a single vocabulary word can map to multiple types (e.g., a word functioning as both a noun and a verb), and a type applies to many words. Validated and bounded as a string up to 32 characters via the application tier.

### Contextual Citations & Sources (`dictionary_sources`)
* **Data Collected:** Source type (string up to 32 characters), title (`utf8mb4_unicode_ci`), and an optional URL (up to 2048 characters).
* **Relationships:** Act as documentation origins for usage examples.

### Sentence Examples (`dictionary_examples`)
* **Data Collected:** Parallel text blocks featuring the raw Vietnamese contextual sentence and its direct `english_translation`.
* **Localization Rule:** Text fields must natively support Vietnamese diacritics without character corruption (`utf8mb4_unicode_ci` collation).
* **Relationships:** Each example is strictly tied to one parent vocabulary word and one documentation source.
* **Data Lifecycle Rule:** If either the parent word or the associated documentation source is deleted, all dependent sentence examples must be automatically cleaned up via a native database-level **Cascade Delete**.

### Etymology & Roots (`han_viet_roots`)
* **Data Collected:** The unique lowercase alphanumeric root, its corresponding Chinese character logogram (`chinese_character`), and the core English `root_meaning`.
* **Relationships:** Connects to vocabulary words via the `word_han_viet_association` junction table to map etymological history. Multiple words can share the same root, and a single word can be composed of multiple roots.

## 7. Verification & Acceptance Criteria

* Autocomplete suggestions yield targeted matching data blocks in under 2ms via the prefix database index.
* Duplicate verification checks kick off smoothly 400ms after typing pauses, catching existing database rows before form submission.
* Breaking a connection via **"Unlink"** cleans up the associative reference mapping in `word_han_viet_association` while keeping the master Hán Việt root entry functional for alternative word combinations.

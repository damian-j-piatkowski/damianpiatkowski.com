# Product Requirement Document: v1.4.0 Dictionary & Admin Panel

## 1. Executive Summary & Core Objective

Milestone 1.4.0 introduces a Vietnamese-English dictionary and learning component to the existing `damianpiatkowski.com` Flask application. The milestone establishes a high-performance dictionary lookup experience together with an authenticated administrative workspace for creating, editing, and maintaining dictionary data.

The primary objective is to introduce a structured, web-based workflow for managing Vietnamese-English dictionary entries within the existing website, while preserving the application's architecture, database migration process, and data-integrity conventions.

The new dictionary functionality will be implemented as an extension of the existing website rather than as a separate application or service. Database schema changes remain managed through the project's existing migration workflow, while dictionary records and their relationships are managed through the new administrative interface.

> **Note on System Continuity:** The dictionary management workflows introduced in this release are designed to integrate with the upcoming Milestone 1.5.0 Reader. When reading an article in 1.5.0, clicking an unknown word will open and automatically pre-populate this same dictionary entry form, allowing dictionary entries to be created from both the administrative workspace and the Reader.

## 2. Admin Authentication & Session Management

Because the website currently requires only a single administrator, the authentication layer uses a lightweight session-based architecture rather than introducing multi-user or role-management functionality.

* **User Storage Schema:** Access is authenticated against the `users` table containing an `id`, unique `username`, and cryptographically hashed `password`. There is no public registration workflow.

* **Login Workflow:** The administrator accesses the dedicated admin login page (e.g., `/admin/login`) and submits their credentials. After successful authentication, the Flask application establishes an authenticated session containing `session["is_admin"] = True`. The session is cryptographically signed and must be protected using the application's secure session configuration.

* **Route Protection Strategy:** A custom `@admin_required` decorator protects admin routes that perform authenticated administrative operations. If the request does not have a valid authenticated admin session, browser requests to protected pages are redirected to the admin login page, while protected mutation requests are rejected appropriately.

The admin login page may remain accessible only through its direct URL rather than being exposed through the public website navigation, but URL obscurity is not relied upon as a security mechanism.

## 4. Detailed User Stories & Functional Workflows

### US1.4.1: Public/Guest Dictionary Search

* **As a:** Guest or Administrator
* **I want to:** type a Vietnamese word or phrase into the dictionary search field
* **So that:** I can quickly find matching dictionary entries.

#### Functional Requirements:

* **Typeahead Search:** The dictionary search provides matching suggestions as the user types.
* **Debounced Search:** Search requests are delayed until the user pauses typing for 200ms, reducing unnecessary requests while typing.
* **Admin Edit Access:** Authenticated administrators see an Edit control alongside dictionary entries in the search results.
* **Entry Modification:** Selecting Edit opens the selected dictionary entry in the modification interface while preserving the current page context.
* **Entry Data:** The modification interface provides the administrator with the dictionary data and relationships required to modify the selected entry.

---

### US1.4.2: New Word Creation Workspace

* **As an:** Authenticated Administrator
* **I want to:** create a new dictionary entry and manage its related information from a single workspace
* **So that:** I can define the word, its grammatical types, translation, contextual examples, sources, and Hán Việt roots in one workflow.

#### Functional Requirements:

* **Duplicate Verification:** After the administrator enters a word, the system checks whether a matching dictionary entry already exists. The check is triggered 400ms after the administrator stops typing.
* **Existing Entry Warning:** If the word already exists, the workspace clearly informs the administrator and provides a direct option to open the existing entry for modification instead of creating a duplicate.
* **Multiple Word Types:** A dictionary entry can have multiple grammatical types. The administrator can add and remove types while creating the entry.
* **Contextual Examples:** The administrator can add one or more example sentences to the entry. Each example includes the Vietnamese sentence, its English translation, and an associated source.
* **Source Selection:** When adding an example, the administrator can select an existing source or search for another source. The interface should make recently used sources readily available.
* **New Source Creation:** If the required source does not exist, the administrator can create a new source by providing a title and, optionally, a URL. The new source can then be associated with the example being created.
* **Hán Việt Root Detection:** For compound words, the administrator can request a check for existing Hán Việt roots. The system identifies the individual component syllables and reports which corresponding roots already exist.
* **Existing Root Association:** When a matching Hán Việt root exists, the administrator can associate it with the dictionary entry.
* **Missing Root Creation:** When a required Hán Việt root does not exist, the administrator can create the root from within the same workflow and associate it with the dictionary entry.
* **Optional Root Associations:** A dictionary entry can be saved without any Hán Việt root associations when no such roots apply.

---

### US1.4.3: Dictionary Entry Modification

* **As an:** Authenticated Administrator
* **I want to:** open a focused modification workspace for a single dictionary entry
* **So that:** I can update its information, manage its related content, or remove the entry when necessary.

#### Functional Requirements:

* **Entry Editing:** The modification workspace displays the current dictionary entry information and allows the administrator to update individual properties, including the English translation.
* **Example Management:** The workspace displays all contextual examples associated with the entry, including their sources. The administrator can remove individual examples or add new examples with a Vietnamese sentence, English translation, and source.
* **Hán Việt Root Management:** The administrator can view the Hán Việt roots associated with the entry and manage those associations individually.
* **Root Unlinking:** Removing an association between a word and a Hán Việt root must not delete the root itself. The root remains available for other dictionary entries.
* **Root Deletion:** The administrator can delete a Hán Việt root only when it is no longer associated with any dictionary entries. If the root is still associated elsewhere, the system must prevent its deletion and provide the option to unlink the current association instead.
* **Word Deletion:** The administrator can permanently remove the entire dictionary entry. This action requires explicit secondary confirmation before the deletion is performed.

## 5. Operational Validation Requirements

The dictionary management workflows must validate user input before processing changes and provide clear feedback when required information is invalid.

* **Word Validation:** A dictionary word cannot be blank and must conform to the allowed character rules. Invalid input prevents the entry from being submitted and provides clear feedback to the administrator.
* **Form Validation:** All required fields must pass validation before an entry can be saved. When validation fails, the administrator is shown clear information about the affected fields and the save operation is prevented.
* **Root Deletion Safety:** A Hán Việt root can only be permanently deleted when it is no longer associated with any dictionary entries. If associations remain, the system prevents the deletion and provides the administrator with the option to unlink the relevant associations instead.
* **Source Validation:** A newly created source must have a title. The source cannot be saved until the required title has been provided.

## 6. Core Data & Relationship Requirements

### User Accounts
* The system stores the credentials required for administrator authentication.
* Each account has a unique username.
* Passwords are stored only as securely cryptographically hashed values.
* Public user registration is not required.

### Dictionary Vocabulary
* Each dictionary entry represents a Vietnamese word or phrase together with its English translation.
* A Vietnamese word must be unique within the dictionary.
* Dictionary searches must support fast lookup of Vietnamese words suitable for interactive search and autocomplete.
* A dictionary entry can be associated with multiple grammatical or word-type classifications.
* A dictionary entry can be associated with multiple Hán Việt roots.

### Word Type Classifications
* A dictionary entry can have multiple word-type classifications, and each classification can apply to multiple dictionary entries.
* This relationship allows a single Vietnamese word to be represented as more than one grammatical type where appropriate.
* Word-type values must be validated by the application and constrained to the supported format.

### Contextual Sources
Sources represent the origins of contextual sentence examples used to document dictionary entries. Each source contains:
* a source type;
* a title; and
* an optional URL.

A source can be associated with multiple contextual examples.

### Sentence Examples
Contextual examples provide Vietnamese usage examples together with their English translations.
* Each example belongs to exactly one dictionary entry.
* Each example is associated with exactly one source.
* Vietnamese text must support diacritics and other characters required for correct Vietnamese representation.
* If a dictionary entry is deleted, its associated examples must also be removed.
* If a source is deleted, its associated examples must also be removed.

*These lifecycle rules ensure that examples cannot remain attached to dictionary data that no longer exists.*

### Hán Việt Roots
Hán Việt roots represent individual linguistic components that can be associated with Vietnamese dictionary entries. Each root contains:
* the root text;
* its corresponding Chinese character; and
* its English meaning.

The relationship between dictionary entries and Hán Việt roots is **many-to-many**:
* a dictionary entry can contain multiple Hán Việt roots;
* a Hán Việt root can be shared by multiple dictionary entries.

Removing the association between a word and a Hán Việt root must not by itself delete the root, because the same root may be used by other dictionary entries.

## 7. Verification & Acceptance Criteria

* **Autocomplete Performance:** Dictionary autocomplete returns targeted matching results quickly enough to provide a responsive interactive search experience, using the database lookup path optimized for Vietnamese-word prefix searches.
* **Duplicate Verification:** The dictionary duplicate check is initiated 400ms after the administrator stops typing and identifies an existing dictionary entry before the new entry can be submitted as a duplicate.
* **Hán Việt Root Unlinking:** Removing a word-to-root association deletes only the corresponding association record in `word_han_viet_association`. The Hán Việt root itself remains available for association with other dictionary entries.
